# Contributing to Marquio

Marquio helps designers finish real editable brand manuals. Read [PRODUCT.md](PRODUCT.md), [DESIGN.md](DESIGN.md) and [AGENTS.md](AGENTS.md) before changing product behavior.

Use Node.js 22+, `npm ci`, `npx playwright install chromium` and `npm run build`. For Linux browser dependencies use `npx playwright install --with-deps chromium`. Install Poppler for `pdftotext` in real PDF tests. Start the compiled application with `node bin/marquio.mjs studio ./my-test-project`; use temporary projects for development, never someone else's client folder.

Run `npm run typecheck`, `npm run build`, `npm test`, `npm run test:e2e` and `npm pack --dry-run` before submitting a change. Focused tests belong in `tests/**/*.test.ts`; real browser flows belong in `tests/browser/*.spec.ts`. Build before tests that execute Chromium export or installed launchers. CI runs these checks on Linux with Node 22. Do not publish or deploy as a test.

Keep changes reviewable. Explain the user-visible problem, resulting behavior and relevant verification in the pull request. Include real screenshots for interface changes. New document fields need validation, portable compatibility and revision-safe commands. Do not bypass repository saves or silently reset documents when validation fails.

Preserve optional/skipped sections, designer approval, provenance, local undo/recovery and the shared render tree. Agent adapters use the same canonical CLI and latest confirmed revision. Installation tests must use explicit temporary roots and preserve existing skills unless replacement is requested. Keep the legacy template/script available during migration.

Only contribute materials you may distribute. Client files, private reference documents, extracted commercial fonts and session URLs do not belong in examples or screenshots. Use the fictitious Aurora fixture and document original asset provenance. See [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md); do not describe generated scenes as real client production.

## Adding a mockup preset or calibrated scene

1. Add a stable, unique preset ID to [`src/mockups/presets.ts`](src/mockups/presets.ts). Supply the version, template, name, scene/composition/material/camera/surface direction, identity requirements and honest usage guidance. Use `application: 'planar'` only for a flat surface; fabric, embroidery, curved or otherwise deformed surfaces use `finished-image` and an explicitly reviewed imported result. The prompt/provider boundary lives in [`src/mockups/prompts.ts`](src/mockups/prompts.ts) and [`src/mockups/providers.ts`](src/mockups/providers.ts); a prompt does not establish that a provider generated a photograph.
2. Put distributable scene media in `public/mockups/` and register it in [`src/mockups/scenes-data.json`](src/mockups/scenes-data.json). Record the exact image width/height, a unique scene ID, relative filename and individually named surface IDs. Connect the preset's `builtinSceneId` to that scene. Keep original/generated provenance and permitted redistribution documented in [`public/mockups/PROVENANCE.md`](public/mockups/PROVENANCE.md) and adjacent prompt files and relevant notices; never use private reference or client material as a public fixture.
3. Calibrate each flat surface with four corners in **top-left, top-right, bottom-right, bottom-left** order. Coordinates are local image pixels measured from the source image's top-left, not percentages or editor screen coordinates. Keep corners finite, in bounds and non-crossing with nonzero area. [`createSceneMockup`](src/mockups/scenes.ts) scales these pixels to the node's local width/height and validates the perspective. A second plane needs its own application; resizing the container must preserve scene/art registration.
4. Supply full-surface artwork composed for the surface's aspect ratio, using `public/demo-artwork/` for original demonstrations. Preset identity requirements guide inputs to a prompt; they do not authorize stretching an isolated logo across a card or screen. Import/register scene, artwork and any extra media bytes before saving the node. Preserve pending approval until the designer approves insertion or replacement.
5. Optional `maskAssetId` masks the artwork/application layer in scene-sized local coordinates; prepare alpha transparency for occlusion and align it to the full scene. `overlayAssetId` paints over the scene and artwork at the node bounds, for a separately supplied light/reflection/foreground layer. These layers need their own imported assets; the renderer does not infer them from a photograph. Finished-image mode keeps a replaceable image child and does not simulate cloth or embroidery.
6. Run `npm test -- tests/mockups tests/render/projection.test.ts`, then build and run `npm run test:e2e -- tests/browser/editor.spec.ts tests/browser/render.spec.ts tests/browser/runtime.integration.spec.ts`. Add coverage for the new IDs and calibrated surface. Inspect real imported artwork at all four edges in the browser and PDF, plus mask/overlay registration, replacement, undo/redo and reopening. Existing rectangular SVG/raster pixel proofs protect projection fidelity; include equivalent evidence for any new behavior. Run the full checks above before submitting.
